Network Data Viewer

Privacy Policy — Last updated 2026-05-26

Network Data Viewer does not collect, transmit, or store any user data beyond what you explicitly configure. Analyser settings are saved in chrome.storage.local on your own device and are never sent off-device by this extension.

What the extension reads

To observe outgoing network traffic, the extension injects a content script that monkey-patches four browser APIs in the page's JavaScript environment:

  • fetch
  • XMLHttpRequest
  • navigator.sendBeacon
  • WebSocket

When one of these APIs is called by the page, the extension captures a copy of the request (URL, method, headers, body) and, where available, the response (status, headers, body). This captured data is processed locally — entirely within your browser — and displayed in the extension's side panel. It is never sent to any remote server, analytics service, or third party.

What the extension does NOT do

  • Does not read cookies, passwords, or form fields outside of network request bodies.
  • Does not modify, redirect, or block any network request.
  • Does not make any external network calls of its own.
  • Does not access your browsing history.
  • Does not run any remote code. All logic executes locally; sandbox code you author runs inside a CSP-isolated iframe with no chrome.* access, no network, and no cookies.

Storage

The extension stores analyser configurations (URL patterns, DSL chains, sandbox code snippets, and the "show raw" toggle) in chrome.storage.local. This storage is sandboxed per-extension and is not shared with websites or other extensions. It is not synced to Google's servers unless you have separately enabled Chrome Sync for extension data in your browser settings.

Captured network events are held only in the side panel's in-memory state for the duration of the browser session. They are never written to disk and disappear when the panel or the browser is closed.

Permissions

The extension declares the following permissions. See permissions-justification.md for the full per-permission rationale provided to the Chrome Web Store.

  • storage — save your analyser configs and settings across browser sessions.
  • sidePanel — render the live event tail in Chrome's side panel surface.
  • offscreen — host the offscreen document that runs sandboxed analyser code inside CSP-isolated iframes (required by Chrome MV3 because a service worker cannot run user-authored code directly).
  • Host access (<all_urls>) — inject content scripts into pages so that fetch, XMLHttpRequest, sendBeacon, and WebSocket can be intercepted. Without this, the extension cannot observe network traffic on the pages you visit.
